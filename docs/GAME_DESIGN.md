# Game design direction

## Core fantasy

The player moves from left to right through compact 3D spaces while physically transporting one deliberately awkward object to the finish.

This is **not primarily a puzzle game**. The destination should usually be obvious. The challenge and comedy come from the physical struggle of carrying, dragging, rotating, pushing, pulling, dropping, recovering, and throwing inconvenient objects.

The intended player reaction is closer to:

> “Why did the developer make me carry THIS?”

than:

> “What is the solution to this puzzle?”

## Core interaction verbs

- walk / reposition
- tap push
- hold grab
- one-hand / two-hand grab
- re-grab from another point
- pull
- push
- drag along the floor
- lift one edge
- lower one edge
- rotate with torque
- pivot around a contact point
- rock a heavy object to build momentum
- tip / roll / cant an object
- drop
- swipe throw
- catch / recover light objects
- lose grip under excessive force

## Difficulty principle

The controls must be precise. Difficulty must come from the **object**, not input latency or bugs.

Different objects should feel materially different through mass, center of mass, dimensions, friction, angular inertia, grip difficulty, and geometry.

Examples:

- sofa: wide, catches on door frames and corners;
- refrigerator: too heavy for casual carrying, better tilted or dragged;
- mattress: wide and visually obstructive, slightly deformable presentation;
- giant fish: long and slippery;
- barrel: heavy but rollable;
- long board/ladder: difficult to rotate in confined spaces.

## Level principle

A good level can be as simple as:

**one sofa + one doorway + one staircase + one truck.**

No complicated switches or code-lock logic is required for the core experience.
